## Why

A repo can have written rules (UI/UX standards, changelog rules, conventions), but nothing makes the agent consult them while it writes a proposal, design or task list. In Second_Brain a locked Telegram UI/UX ruleset existed and a later proposal ignored it: AGENTS.md never pointed at it, and `/opsx:propose` only reads code and nearby docs. Reading rules "when relevant" fails because relevance is left to the agent's memory.

## What Changes

- **AGENTS template** (`.agents/templates/AGENTS-template.md`): a new "Repo rules" section right after Project Overview. It has an index table (Rule file | Summary | Applies when) whose triggers are observable conditions, not topics, and the requirement text: before writing a proposal, design or tasks, read every rule file whose trigger matches the change, make each a constraint on that artifact, and state in the artifact how it was applied.
- **Both schemas** (`spec-driven-verified`, `econometric-verified`): the instructions of the proposal, design and tasks artifacts gain one generic step that follows the repo's AGENTS.md "Repo rules" section when it exists and does nothing when it does not. The artifact templates gain a "Rules applied" slot, and the verification template gains a check that the cited rules were followed. `econometric-verified` has no `design` artifact, so `identification` takes that role there.
- **Skills:** `rules-template-author` adds the new section to its "Template Must Cover" list. `openspec-verify` gets one line so its reviewer reads the cited rule files and checks conformance; without it the reviewer is never pointed at them.
- **Deploy:** the last task runs the sync script (`-WhatIf` first, then the real run after owner confirmation), because OpenSpec reads the schema from `%LOCALAPPDATA%\openspec\schemas\`, not from this repo.

Not changing: `openspec/config.yaml` in any repo, `openspec-mod/README.md`, the generated `openspec-propose`/`openspec-apply` skills (regenerated by `openspec update`), the installer, `/opsx:apply` behavior, and Second_Brain's own AGENTS.md (a separate follow-up).

### Modified Capabilities
- `econometric-team/schema`: the `econometric-verified` schema directs the agent to consult and apply matching repo rules when writing its proposal, identification and tasks artifacts, and its verification step checks the cited rules. The programming schema `spec-driven-verified` has no spec and changes only in `schema.yaml` and its templates.

## Impact

- Framework files: `.agents/templates/AGENTS-template.md`, `openspec-mod/openspec-schemas/spec-driven-verified/` (`schema.yaml`, proposal, design, tasks and verification templates), `openspec/schemas/econometric-verified/` (`schema.yaml`, proposal, identification, tasks and verification templates), `.agents/skills/rules-template-author/SKILL.md`, `openspec-mod/claude-skills/openspec-verify/SKILL.md`, and the spec `openspec/specs/econometric-team/schema/spec.md`.
- Outside the repo: the deployed schema and skill copies (user OpenSpec schema folder, Claude and Codex skill folders), updated only by the final sync task.
- Repos that already installed the template do not change; they adopt the section by copying it. A repo without a "Repo rules" section sees no behavior change.
